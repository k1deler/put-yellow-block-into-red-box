# 两份黄块任务模型的对比与新模型路线

本文件区分：已有模型的事实、待测比较、以及尚未开始的训练。不会把改名、格式转换或权重平均写成“训练了新模型”。

## 已知差异

| 项目 | 个人已有 `act_best.pt` | 已运行的 `block_bowl_delta.pt` |
|---|---|---|
| 来源 | `task1_model_comparison_20261029` 训练产物 | fufu / yam_train 导出的黄块任务权重 |
| 格式／实现 | `kideler-task1-act-v1`，LeRobot ACT 0.4.4 | `yam_train/act_ref-v1`，ACT参考实现 |
| 训练参数量 | 配置记载 51,570,574 | 实验室实际加载输出约83.92M |
| 图像 | 左、右；240×320；Pillow双线性缩放 | 以checkpoint顺序为准，已有记录右、左；480×640；JPEG往返 |
| 状态归一化 | 训练集逐维limits的scale/offset | checkpoint的qpos_mean/std |
| 动作反归一化 | `(raw - offset) / scale` | `raw * action_std + action_mean` |
| 关节还原 | 12个关节加同一次观测anchor | delta模式全部14维加同一次观测anchor |
| 夹爪还原 | 绝对目标，不加anchor | 当前delta分支也加夹爪anchor，随后过滤至合法范围 |
| 输出时间 | 内部16步，部署取前8步，30Hz | 100步，30Hz；当前执行每60步切换计划 |
| 模型起始姿态 | 原部署没有模型内置回位链路 | 模型保存start_pose，运行前对齐 |
| 已有离线数值 | 关节MAE约0.02546rad，夹爪MAE约0.04723，夹爪有越界 | 当前没有相同数据划分和标签语义下可比较的离线MAE |
| 实机证据 | 原入口曾因初始反馈／目标越界拒绝；不足以判断网络优劣 | 用户反馈新部署“效果不错”，不是多轮成功率统计 |

个人模型的6.79ms中位推理延迟来自H20，仅包含GPU模型及动作还原，不含图像、传输和控制，不能与实验室RTX5090的整体执行时间直接比较。指标、参数量或文件体积也不能单独证明哪个模型抓取更好。

## 比较前先统一什么

1. 固定同一任务与相机颜色、左右身份、起始场景。明确数据中的action是主臂重建目标还是未来从臂反馈；两者不能混成同一监督标签。
2. 按完整episode划分训练／验证／最终测试，保存文件SHA和排除名单；同一演示的相邻帧不跨集合。
3. 为两种模型分别保留正确预处理与动作还原，统一到同一时刻、同一14维物理绝对目标后再计算误差。
4. 比较关节和夹爪分开MAE、静止保持基线、运动窗口／夹爪过渡误差、越界率、推理端到端延迟。不要裁剪掉越界后只报告好看的误差。
5. 候选模型过离线门槛后，在相同现场条件下多轮对比成功率、抓空、滑落、放置失败和保护停止。权重更换与代码更换分开提交，保留已跑通基线。

## 建议的新模型方式

优先保留已经跑通的`yam_train/act_ref-v1`推理合同，用自己的新增成功示范做微调；这样仍可使用已验证的起始姿态、相机处理和控制接口。新权重需要真实训练及新的checkpoint元数据，不通过合并两种不兼容网络得到。

这是建议路线，不是已执行的训练。微调须记录初始权重SHA、数据SHA、episode划分、随机种子、更新参数、优化器、学习率、训练／选择步数、归一化、动作语义和来源。若保持输出头学习原合同，不能擅自把夹爪delta改成绝对；要改变语义就必须连同数据、归一化、推理适配和验证整体更新。

发布描述应准确写作“基于注明来源的ACT实现和初始权重，使用自己的数据微调并验证”，不把基线或第三方架构说成全部自行原创。如果从随机初始化重新训练，应明确写明，并与微调结果分别比较。
